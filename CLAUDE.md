# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Two coupled but distinct concerns live here:

1. **Cluster bootstrap (repo root)** — Sidero Omni templates that provision a Talos
   Kubernetes cluster with Cilium as CNI. Applied with `omnictl`, not `kubectl`.
2. **GitOps workloads (`GitOps/clusters/cyberhawk-talos-k8s/`)** — everything running
   *on* the cluster, reconciled by Argo CD from this same Git repo.

The cluster is `cyberhawk-talos-k8s-01`. It is multi-site (topology zones `lorenskog`,
`blix`) joined over Kubespan; Cilium is configured to masquerade pod traffic between
sites.

## Cluster bootstrap (repo root)

`template.yaml` is the Omni cluster template: it defines the Cluster, ControlPlane
(3 nodes via machineclass `role-controlplane`), and Workers, and wires in patches from
`patches/`. `machineclass.yaml` defines how Omni discovers/auto-provisions machines.
`machine-patches.yaml` holds **per-machine** Omni `ConfigPatches` (control-plane
topology-zone labels, worker hostnames) — the template cannot carry per-machine patches
for machineClass-allocated machines, so these are applied separately.

Cilium and Argo CD are installed as Talos **inline manifests** baked into patch files.
Those patch files are generated by `helm template` and are **gitignored**
(`patches/install_cilium.yaml`, `patches/install_argocd.yaml`) — they must be
regenerated before applying the template, otherwise a template sync can **downgrade**
the live Cilium/Argo CD to whatever stale version the local files hold.

Deploy/update the cluster: regenerate both inline-manifest patches, then `omnictl apply`
`machineclass.yaml` and `machine-patches.yaml` and run `omnictl cluster template sync
--file template.yaml`. Full commands and the helm-template heredoc are in `README.md`.

`patches/cni.yml` disables the default CNI; `patches/kubespan.yml` enables Kubespan;
the `gvisor-*` and `monitoring*` / `etcd-timeouts` patches tune Talos.
`patches/extraManifests.yml` URLs are pinned to release tags with `# renovate:` comments.
(`zswap.yaml` and `enable_helm.yaml` are leftovers no longer referenced by the template.)

## GitOps layout & the ApplicationSet (the key architecture)

`1-system/argocd/appset.yaml` is the heart of the GitOps model. A single Argo CD
**ApplicationSet** uses a git-directory generator to auto-discover folders and create
one Argo CD `Application` per directory — there are almost no hand-written `Application`
manifests (exception: `volsync-system`). **To add a workload you create a
directory; you do not register it anywhere.**

Directories are organized into numbered layers, scanned at two depths:

- `1-system/` — cluster infrastructure (argocd, cilium, cnpg, mariadb-operator, CSI, gateway, kyverno, tetragon)
- `2-services/` — platform services (cert-manager, dnscontrol, monitoring, openbao, newt, volsync, keda)
- `3-apps/` — applications (geopulse, it-tools, karakeep)

Additional workloads live in a separate **private** repo, sourced by a second
ApplicationSet (`1-system/argocd/appset-private.yaml`) using the SOPS-encrypted
deploy-key credential in `1-system/argocd/repo-private-secret.sops.yaml`.

Discovery & naming rules baked into the generator:

- **Level 1** (`<layer>/<name>/`) → app named `<layer>-<name>`, deployed to namespace `<name>`.
- **Level 2** (`<layer>/<group>/<app>/`) → app named `<layer>-<group>-<app>`, deployed
  to namespace `<group>` (the parent dir). This is why `librenms` lives under
  `2-services/monitoring/librenms/` and lands in the `monitoring` namespace.
- A directory named `namespaces` deploys to `default`.
- **Dot-prefixed dirs are skipped** by the generator — renaming `portfolio/` to
  `.portfolio/` is how that app is currently disabled without deleting it (Argo prunes
  the workload; the namespace and kyverno references remain).

Every discovered leaf directory **must contain a `kustomization.yaml`** (or a Helm
chart) that Argo CD can build. Sync policy is automated with `prune: true` and
`selfHeal: false`, server-side apply, `CreateNamespace=true`.

## Observability stack (`2-services/monitoring/` + `1-system/tetragon/`)

kube-prometheus-stack + Loki + Alloy + Gatus + Tetragon (observe-only, never enforcement).
**Read `docs/monitoring/README.md` before editing either directory.** It holds the
gotchas that cause silent "No data" / OutOfSync: only `release: monitoring` monitors are
scraped, no blanket `namespace:` transformer in the kps kustomization, etcd is a static
scrape, kps major upgrades need CRDs applied first, and Gatus probes user apps by public
hostname. Control-plane IPs: ctrl-00 `10.50.1.50`, ctrl-01 `10.50.1.51` (blix), ctrl-02
`192.168.155.10` (lørenskog); worker-01 `192.168.155.100` is lørenskog.

## Conventions for workload directories

- **File ordering by numeric prefix.** Files are named `NN-purpose.yaml` (e.g.
  `01-secret.yaml`, `10-mariadb.yaml`, `31-librenms-deployment.yaml`) so kustomize/Argo
  apply them in a sensible order. Follow the existing numbering when adding files.
- **Image versions are pinned in `kustomization.yaml`** via the `images:` block
  (`newTag`), not in the Deployment manifests. Bump versions there. A self-hosted
  **Renovate** CronJob (`2-services/monitoring/renovate/`, config in repo-root
  `renovate.json`) opens PRs for these; pins living outside a kustomization (raw
  manifests, CNPG `imageName`, extraManifests URLs) need a
  `# renovate: docker=…`/`helm=…`/`github-release=…` comment to be tracked.
- **Databases via operators.** MariaDB-backed apps reference `MariaDB`/`Database`/`User`/
  `Grant` CRs (mariadb-operator); Postgres uses CNPG. Don't hand-roll DB StatefulSets.
- **Kyverno admission policies** (`1-system/kyverno/`): disallow-latest-tag,
  require-labels, and restrict-image-registries **Enforce** in the namespaces
  listed in each policy's `failureActionOverrides` (Audit elsewhere); PSS-restricted
  is audit-only. New workloads should carry `app.kubernetes.io/name` + pinned, allowed-registry images or they'll show up in
  PolicyReports (and be blocked in Enforce namespaces). Break-glass:
  `docs/kyverno/break-glass.md`.

## Secrets: SOPS + KSOPS

Secrets are committed **encrypted** as `*.sops.yaml`, encrypted with **age** via SOPS
(see `.sops.yaml`; only `data`/`stringData` fields are encrypted). Argo CD decrypts them
at apply time using the **KSOPS** kustomize plugin, installed into `argocd-repo-server`
by `1-system/argocd/argocd-repo-server-patch.yaml` (age key mounted from the
`argocd-sops-age-key` secret).

To consume a secret in a kustomization, reference it through a **ksops generator**, not
as a plain resource:

```yaml
# kustomization.yaml
generators:
  - 01-secret.yaml        # a viaduct.ai/v1 ksops manifest pointing at 01-secret.sops.yaml
```

Edit secrets with `sops <file>.sops.yaml` (requires the age private key locally). The
bootstrap age key is loaded into the cluster with:

```bash
cat keys.txt | kubectl -n argocd create secret generic argocd-sops-age-key --from-file=keys.txt=/dev/stdin
```

## Operational notes

- This is a config/manifest repo — there is no build/test/lint suite. "Correctness" =
  the manifests render (`kustomize build <dir>`) and Argo CD reports the Application
  Synced/Healthy.
- Argo CD reconciles from `HEAD` of `main` on
  `github.com/jochristian/omni-templates-cyberhawk`, so changes take effect only after
  they are pushed.
- **`kubectl` access uses Omni OIDC** (`oidc-login` exec plugin, `--skip-open-browser`).
  On a headless host the token expires and `kubectl` then **hangs** (no browser to
  re-auth). Refresh non-interactively with
  `omnictl kubeconfig -c cyberhawk-talos-k8s-01 --service-account --user <name> --ttl 720h -f`
  (or `--grant-type authcode-keyboard`). This needs an omniconfig at `~/.config/omni/config.yaml`.
- **DNS is GitOps too:** all public zones are managed by dnscontrol
  (`2-services/dnscontrol/` — zone config + Cloudflare token in one SOPS secret; PostSync
  hook pushes on sync, nightly drift CronJob reverts manual Cloudflare-UI edits). Edit
  records with `sops 01-dnscontrol.sops.yaml`; workflow in `docs/dnscontrol/README.md`.
- `docs/` runbooks: `docs/monitoring/` (observability stack + gotchas), `docs/openbao/`
  (operator runbook, SOPS workflow, agent-injector examples, user guide), `docs/dnscontrol/` (DNS change/preview workflow),
  `docs/kyverno/break-glass.md` (bypass a blocking policy), `docs/geopulse/`
  (Home Assistant GPS source), `docs/tetragon/policy-matches.sh` (runtime policy-match
  viewer). `**/docs/superpowers/` is local-only (gitignored).
